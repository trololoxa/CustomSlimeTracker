# Magnetic heading reliability and continuous axis candidates

Patch 0022 introduced temporal magnetic-field reliability, large-error yaw
reacquisition and background `magToImu` candidate collection. Hotfix 0022a
added continuous `SO(3)` refinement and moved solver/storage work out of the
magnetic sample callback. Post-audit hotfix 0022b closes the remaining moderate
stationary field-jump, rate-dependent confidence, in-sample proof and deferred
realtime-scheduling gaps. None of these patches replaces the 6DoF AHRS, changes
IMU/FIFO configuration, or automatically promotes active calibration.

## Runtime pipeline

```text
QMC6309 sensor-hub sample
  -> hard/soft-iron calibration
  -> mag-to-IMU proper rotation when valid
  -> sensor-to-device frame
  -> world heading and dip
  -> temporal field-reliability monitor
  -> yaw normal/reacquisition gate
  -> bounded world-up yaw correction
```

The reliability state is one of:

```text
unavailable -> acquiring -> trusted
trusted -> suspect -> disturbed -> recovering -> trusted
```

The monitor compares field norm and world-frame dip with a slowly adapted
reference and observes sudden magnetic-direction changes while the tracker is
stationary. The stationary discontinuity signal is `magnetic north world yaw -
AHRS yaw`, so a bounded magnetic yaw correction or an AHRS yaw-frame reset rotates
both terms together and cannot masquerade as a local field jump. 0022b keeps a
short stationary anchor and latches cumulative changes that are faster than both
plausible gyro drift and the normal 2 deg/s yaw-correction limit. This catches
stable 5-19 degree local field jumps that previously cleared the ordinary
one-sample suspect gate. The latch is disabled during actual motion by the
gyro/accel stationary gate. Reference acquisition averages a stable window instead
of copying one sample. Heading rate used by reacquisition is a signed low-pass
estimate of the same AHRS-yaw-removed field signal, so ordinary QMC jitter or an
internal yaw correction cannot reset the reacquisition dwell forever.

A stable field whose direction abruptly changes away from the established
reference remains fail-closed after the long environment dwell. It is reported
with `environment_changed` and is not made yaw-trusted while the old reference
remains. Returning to the original field enters the normal recovery dwell. If the
tracker has remained stationary since the latch, return may also be proven against
the stored pre-jump body-relative field signal; this prevents a permanent lockout
when ordinary 6DoF yaw drift accumulates while magnetic correction is disabled.
Any detected physical motion disables that shortcut, leaving only the absolute
world-field return or an explicit clear/reacquire. A stable shifted field is never
automatically adopted as a new environment.

Yaw correction is allowed only in the trusted state. Ordinary correction keeps
the strict innovation limit. A larger finite yaw error enters a separate
reacquisition path instead of renewing cooldown indefinitely. Reacquisition
requires a long trusted-field interval, low gyro motion, high accel trust and low
filtered magnetic-heading rate, then applies a slower rate- and step-limited
world-up correction. Magnetic data never directly changes roll or pitch.

## Two-stage continuous mag-axis solver

The runtime collector observes coherent gyro and calibrated magnetometer pairs.
It uses the two timestamp-coherent endpoint gyros as a trapezoidal interval-rate
estimate, avoiding an additional 960 Hz learner hook in the IMU hot path.
For each finite interval it compares the measured next magnetic direction with
the exact constant-angular-rate body-frame prediction:

```text
m1_predicted = Exp(-omega * dt) * m0
```

This avoids the first-order `dm/dt = -omega x m` bias that becomes visible when
estimating residual sensor misalignment of only a few degrees.

The solver has two stages:

1. Search the 24 right-handed signed axis permutations (`det = +1`) to determine
   the coarse axis order and signs. Reflections are not physical sensor-frame
   rotations and are not generated by new setup/runtime/manual results.
2. Refine the best coarse hypotheses with a bounded local `SO(3)` search. The
   result remains orthonormal with determinant `+1` and may represent real
   mechanical placement error such as a two-degree residual rotation.

The refinement is bounded to 12 degrees around its coarse seed. It never
optimizes an arbitrary 3x3 scale/shear matrix and therefore does not absorb
hard/soft-iron calibration into `magToImu`. Existing persisted legacy mappings
remain readable for compatibility; newly generated or manually entered mappings
must be proper rotations.

Retained temporal windows are deterministically split into independent training
and validation partitions. Coarse search and continuous refinement use only the
training windows. The winning refined hypothesis, its runner-up and the active
matrix are then scored on held-out windows. A candidate is staged only when the
same hypothesis wins validation, the training-to-validation gap is bounded, the
held-out score beats active calibration and coverage/excitation are sufficient.
Confidence uses separation normalized by observable magnetic angular motion, so
ordinary 30-120 deg/s movements are comparable with faster sweeps instead of
being rejected by a fixed degree margin. If the result is angularly equivalent
to active calibration, the collector records confirmation and resets without
creating a candidate.

## Realtime and storage boundary

The 60 Hz magnetic callback only validates/coherently collects observations and
sets a pending action. Solver and candidate-storage work run later from the normal
app loop. 0022b requires the software queue to be idle, reads the real LSM FIFO
status, rejects watermark/full/overrun or more than eight unread words, and also
requires safe slack before the next armed SlimeVR rotation deadline. One deferred
action is serviced per loop and every reject reason is counted.

Candidate presence uses a lightweight fail-closed key check instead of a full
active-slot inspection. Solver and storage calls expose count, deferral and
last/max-duration counters. This removes repeated slot scans and heap/NVS work
from the magnetic sample callback, but real ESP32 NVS latency still requires the
hardware acceptance test below.

Collection and solving are bounded:

- timestamp-skew, hard/soft validity and calibration ownership are checked before
  collection;
- alignment learning uses axis-independent calibrated finite/in-range samples so
  a bad-but-formally-valid active `magToImu` cannot block its own replacement;
- train/holdout proof rejects transient or non-rigid magnetic changes that do not
  reproduce across independent temporal windows;
- no solve occurs before minimum interval/window/axis coverage;
- solve attempts and occupied-slot probes are rate-limited;
- active hard/soft calibration capture pauses background axis collection;
- storage read failure is fail-closed;
- a weak, active-equivalent or non-improving result is discarded in RAM;
- a proven result is staged only as a RAM calibration candidate;
- there is no automatic flush, promotion, active-config mutation or FIFO restart.

## Candidate quality and promotion

A background axis result stores measured solver quality in the existing candidate
metadata and marks the alignment quality as measured. Old active generations only
stored binary alignment validity. During comparison, that legacy `1.0` is treated
as an unmeasured neutral baseline only when the candidate carries measured axis
quality; the runtime solver has already compared candidate and active matrices on
both independent training and held-out validation partitions before staging.

This allows the normal safe path:

```text
background solve
  -> RAM candidate
  -> cal candidate compare
  -> cal candidate flush
  -> cal candidate promote
```

A genuinely better candidate no longer requires `promote force`. Promotion still
uses the 0021 calibration-only transaction, signature, freshness and rollback
rules. It never changes ODR, FIFO, SPI, network or output policy.

The candidate is intentionally not applied or deleted automatically in 0022b.
Autonomous repeated confirmation, promotion, probation, rollback and cleanup are
the scope of 0023. Until then use:

```text
mag heading
mag yaw status
cal candidate status
cal candidate compare
cal candidate flush
cal candidate promote
cal candidate discard
```

## High-dip horizontal observability

Yaw observability depends on the horizontal component of the local magnetic
field, not on total field norm alone. The old fixed `200/260` horizontal gate
rejected a healthy hardware field with norm about 444 and dip about -70.5 degrees,
whose physically consistent horizontal component was only about 149.

After the field reference is acquired, one shared pure helper derives the
reference horizontal norm from reference norm and dip. Persisted absolute
`horizontalNormBad/Good` values remain conservative upper caps. A typed
`MagHorizontalTrustConfig` supplies the adaptive reference fractions, absolute
SNR floors and heading-noise scale bounds; the algorithm contains no second hidden
copy of those tuning constants. The default policy lowers thresholds to 35% and
65% of the local reference with absolute floors of 20 and 40. The same result is
used by field reliability, auto-reference and yaw correction, preventing those
three gates from disagreeing.

Stationary heading-jump detection is disabled when horizontal trust is below
0.25. In observable high-dip fields the shared geometry scale multiplies both the
stationary jump angle/rate gates and the older per-sample heading-step soft/hard
gates. The scale is the square root of total-field to horizontal-field ratio,
clamped by the typed policy (default 1..2). Directional heading-step gates are not
evaluated at all while heading is unobservable. This prevents high-inclination
heading noise from repeatedly entering suspect/disturbed state through a legacy
gate after the newer jump detector has already declared the direction unreliable.
Real larger discontinuities remain fail-closed. Low horizontal observability sets
`HORIZONTAL_UNOBSERVABLE`; it closes magnetic yaw use without falsely declaring
norm/dip environment corruption.

CLI diagnostics expose current/reference horizontal norm, effective bad/good
thresholds, horizontal trust, effective stationary jump angle/rate, and the
effective heading-step soft/hard thresholds.

## Diagnostics

`mag heading` and `mag yaw status` expose:

- field state, trust, flags and environment-change count;
- current/reference norm, dip and heading error;
- instantaneous and filtered heading rate;
- yaw normal/reacquisition mode, pending/active state and correction limits;
- continuous-axis interval/window/axis coverage;
- final, coarse, second-best and active solver scores in degrees;
- refinement angle, training/validation scores, normalized separation,
  observable rotation, direction/magnitude errors and measured quality;
- stationary heading-window delta/rate and discontinuity-latch state;
- pending deferred action, service deferrals and solve/storage timing counters;
- timestamp-skew rejects and candidate stage state.

Machine-log `LOGVER` remains 3. Existing fields retain their positions.
`field_heading_rate_deg_s` is the filtered rate used by reacquisition; the
instantaneous rate is available in CLI diagnostics. The parser remains compatible
with older logs.

## Hardware acceptance

1. Build and flash every required PlatformIO profile, then verify the feature
   identity is `c3-6dsv-safe-calibration-autonomy-hardened`.
2. With valid hard/soft and axis calibration, keep the tracker still for at least
   three seconds. Require `field_state=trusted` and `field_trusted=yes`.
3. Introduce and remove nearby same-norm directional disturbances of 5, 9, 12,
   19 and more than 20 degrees while still. Every abrupt stationary shift must
   latch fail-closed. The original field must recover after the normal dwell even
   if AHRS yaw drifted while the tracker remained still. Repeat after physical
   motion and require the body-relative shortcut to stay disabled until the
   absolute world field returns or the reference is explicitly cleared. Also
   inject an AHRS-only yaw-frame step and verify it never latches as a field jump.
4. Create a yaw error beyond the normal innovation limit and keep the tracker
   still. Ordinary QMC jitter must not prevent `reacquire_pending` from becoming
   `reacquire_active`; correction must remain within printed rate/step limits.
5. Rotate smoothly around multiple axes at ordinary 30-120 deg/s. Continuous
   coverage should grow and may stage a candidate. Require at least two training
   and two validation windows, matching winners, bounded generalization gap and a
   non-zero bounded refinement when real mechanical offset exists.
6. Run `cal candidate compare`; a proven background axis candidate must compare
   as better and prepare normal promotion without `force`.
7. During solve, slot probe and staging require zero FIFO overrun/full, no tracking
   recovery entry, normal rotation delivery and zero UDP send failures. Inspect
   hardware-FIFO and output-deadline deferral counters, unread-word maxima,
   `axis_solve_max_us` and `axis_storage_max_us`.
8. Verify config generation, FIFO configuration and active `magToImu` remain
   unchanged until explicit promotion. Reboot before `flush` must discard the
   RAM-only candidate; reboot after `flush` must retain it.
