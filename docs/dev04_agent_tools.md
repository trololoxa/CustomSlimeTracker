# DEV-04: инструкции и дополнения для GPT-6 Astra

Проверено 2026-09-22. GPT-6 Astra — предпочтение по умолчанию, не жёсткая
фиксация. По уточнению владельца DEV-04a разрешает выбирать другую доступную
модель для подходящей задачи без отдельного согласования, сохраняя проверку
качества и ограничения проекта. При сомнениях — Astra или более сильная
доступная модель и разбор оставшихся проблем. Выбор модели не доказывает
отсутствие регрессий; фактическую смену нужно кратко обозначить. Патчи не
меняют тариф, account settings или глобальные разрешения. Экономия токенов
в этом проекте пока не измерена; проценты из чужих benchmarks не переносим.

## Аудит AGENTS.md / Skills

В полученном Git-архиве `76ff25c1b7ad4389572e3391f66361efd3b1de33` нет AGENTS.md,
AGENTS.override.md и SKILL.md. Пользовательские/global Skills и конфигурация
локального Codex не приложены: их конфликтность здесь не проверена.

[Статья OpenAI](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
рекомендует узкие триггеры skills, чтение деталей по необходимости и удаление
обязательных повторяющихся процедур. Применение к Tracker:

| Источник лишней работы | Минимальное решение DEV-04 |
| --- | --- |
| Чтение всех аудитов перед любой правкой | Короткий AGENTS.md с тематическими ссылками |
| Полный gate после каждого изменения | Карта затронутых тестов; full/release при соответствующем объёме |
| Остановка после первого варианта исправления | Явно разрешён законченный локальный цикл исправления/проверки |
| Дублирующие Skills на все coding tasks | Новые Skills не добавлены: сейчас хватит правил и обычных инструментов |
| Каждый раз настройка окружения и поиск команды | Готовые команды возобновления и отдельная проверка source identity |

Это сокращает процедуру, не численные guards и не доказательства качества.
Содержание новых инструкций проверено на повторение и конфликт с контрактом
проекта; их фактическое включение конкретным клиентом Codex ещё надо увидеть
на машине пользователя. [Правила загрузки AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## NVIDIA SoL-Pi

[Официальный репозиторий NVIDIA](https://github.com/NVlabs/SoL-Pi) описывает
расширение для Pi, не для Codex. Четыре механизма: объединение действий,
хранение больших результатов с точным повторным доступом, сокращение логов
отдельной моделью и уплотнение контекста. Все включаются явно.

Для текущего Codex его не устанавливаем. Дополнительный reducer создаёт модельные
вызовы и может передавать логи провайдеру. Полезный принцип уже применим здесь:
короткий итог и доступный исходный лог, без сокрытия ошибок. DEV-03/03a это делают.
Не копируем инструкции из `agents-install.md`: они относятся к установке Pi,
которую пользователь не заказывал. Совместимость при смене harness — отдельный проект.

## Что добавлять и что отложить

Это оценка применимости, не утверждение о проведённом A/B benchmark или установке.

| Дополнение | Решение для Tracker | Причина / условие |
| --- | --- | --- |
| [Serena](https://github.com/oraios/serena) | Первый кандидат для пробного подключения после clangd | Символьная навигация/references через LSP, включая C/C++; проверить правильные flags и hardware/native профиль |
| [RTK](https://github.com/rtk-ai/rtk) | Пока отложить | Фильтрует command output; наши gates уже дают короткий вывод. Не оборачивать эталонные raw logs дополнительным фильтром |
| [jCodeMunch](https://github.com/jgravelle/jcodemunch-mcp) | Альтернатива для поиска, не ставить одновременно со всеми индексаторами | Tree-sitter индекс и выборочное извлечение символов; проверить свежесть индекса и покрытие C++ macros/templates |
| [jDocMunch](https://github.com/jgravelle/jdocmunch-mcp) | Пока необязателен | Навигация по секциям документации; имеет смысл при регулярном поиске по большому внешнему корпусу |
| [Caveman](https://github.com/JuliusBrussee/caveman) | Не включать по умолчанию | Меняет стиль/краткость ответов; понятные команды, единицы и объяснения ошибок для нас важнее дополнительного слоя инструкций |
| [Token Saviour](https://github.com/vagkaratzas/token-saviour) | Пока не добавлять | Ещё один router между Serena/RTK/Caveman и другими инструментами; пересекается с правилами выбора в проекте |
| CodeGraph | Отложить; сначала точный repo | Под этим именем несколько проектов; [один из вариантов](https://github.com/colbymchenry/codegraph) строит индекс/граф. Нужен отдельный выигрыш на C++ references, а не дубликат Serena |
| clangd + compile_commands.json | Подготовить сейчас, установку проверить на рабочем ПК | Основа C++ навигации без нового LLM; DEV-04 экспортирует native commands, target имеет PlatformIO compiledb |
| GDB / OpenOCD / board access | DEV-06 | Для аппаратной диагностики; Linux host GDB сам по себе не доказывает ESP32 JTAG |
| GitHub connector / gh | Когда репозиторий размещён на GitHub | PR/CI workflow; локальный архив не требует внешнего подключения |
| Official OpenAI documentation access | По вопросам самого Codex | Существующего web/docs доступа достаточно; не требуется включать для каждой firmware-правки |

## Как проверить пользу без потери качества

На одном commit сравнить базовый `rg`/прямое чтение с одним кандидатом:
поиск owner/references, локальный fix и разбор failed log. Проверить найденные
места по исходникам, одинаковый итоговый diff/acceptance и отсутствие потерянных
ошибок. Из доступных usage counters записать tokens, tool calls, время; отдельно
учесть запуск сервера, indexing и поддержание индекса после изменения файла.
Не выводить token savings из длины ответа или числа строк. Если инструмент
требует больше контекста/времени без выигрыша, отключить его.

Собственный узкий Skill стоит добавлять, когда DEV-06 определит повторяемый
hardware workflow, который нельзя выразить одной командой. Не создавать
заранее универсальный «всегда проверь всё» Skill.
